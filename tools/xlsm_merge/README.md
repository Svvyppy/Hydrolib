# Слияние Excel-базы Hydrolib

Excel остаётся редактором: формулы и протягивание данных сохраняются.
Обработчик сравнивает общий предок, вашу версию и вторую ветку, сопоставляя
компоненты по паре **лист + Part Number**, поля — по колонке при неизменной схеме.
Для спорных изменений отчёт собирает конфликты данных и позволяет выбрать
`ours` или `theirs` отдельно для каждого. При неподдерживаемом изменении структуры
проверка может остановиться раньше: такие ошибки выбором стороны не обходятся.

## GitHub Actions

После принятия установочного PR в `master`:

1. Обычные PR проходят `XLSM merge check`: тесты, пробное трёхстороннее слияние
   с текущей базовой веткой, артефакт `xlsm-merge-report` с книгой или ошибкой.
2. Если PR конфликтует из-за XLSM, участник с правом записи запускает
   **Actions → Update PR with XLSM merge → Run workflow**, выбирает `master`
   и указывает номер PR. Workflow сливает базовую ветку в ветку PR и отправляет
   merge-коммит без force push. Сам PR в master не принимается автоматически.
3. При конфликте данных скачайте артефакт: в нём `report.json` и три исходные
   книги `ancestor.xlsm`, `ours.xlsm`, `theirs.xlsm`. В полном `report.json`
   измените поле `choice` у каждого конфликта с `null` на `"ours"` либо `"theirs"`.
   Вновь запустите **Update PR with XLSM merge** для того же PR и вставьте
   **весь JSON** в необязательное поле `resolutions_json`. Остальные поля не меняйте.
   В Actions **ours = ветка PR**, **theirs = целевая ветка PR**, например `master`.
   Независимые изменения обеих сторон сохраняются автоматически.
   При конфликте удаления с изменением или добавлении одного ID с разными данными
   выбирается целиком запись выбранной стороны (отсутствие означает удаление).
   При конфликте обычной ячейки выбирается только эта ячейка.
   Не смешивайте JSON от разных PR: решения привязаны SHA-256 ко всем трём книгам.
   Если хотя бы одна книга изменилась, получите новый отчёт и повторите выбор.
   Пока есть `null`, неверное решение или структурная ошибка, push не выполняется.
   Конфликты других файлов также останавливают push.
4. Скачайте/получите книгу, откройте в настольном Excel, выполните полный
   пересчёт (`Ctrl+Alt+F9`) и сохраните перед использованием в Altium.
   Python **не вычисляет** формулы; старые кэши удаляются. Не используйте
   непересчитанный артефакт непосредственно как базу Altium.

Проверка установочного PR не может использовать эти инструменты из старой
базовой ветки, пока они туда не приняты. Локальные тесты проверяют bootstrap.
Push с `GITHUB_TOKEN` обычно не запускает новые workflow: после команды update
может потребоваться повторная проверка PR вручную/новым обычным push. Включите
обязательный статус `XLSM merge check` в правилах ветки, если это нужно команде.
Workflow не меняет правила защиты веток и не обходит запреты репозитория.

PR из fork получает отчёт, но автоматический push в fork не поддерживается.
Код из PR не исполняется привилегированным workflow: используется скрипт из
базовой/default ветки, входные книги читаются как данные, Git hooks отключены.
Не используйте `pull_request_target` для запуска скриптов из PR.

## Локальное слияние

Из корня клона (Python 3.12):

```sh
python -m pip install -r tools/xlsm_merge/requirements.txt
python tools/xlsm_merge/install.py
```

Настройка выполняется каждым участником один раз на клон. Затем обычный
`git merge` использует обработчик. `.gitattributes` без локальной настройки
драйвера недостаточно. Не применяйте этот драйвер к произвольным Excel-книгам.

Для отдельной проверки:

```sh
python tools/xlsm_merge/merge.py base.xlsm ours.xlsm theirs.xlsm merged.xlsm --report report.json
python -m unittest discover -s tests -p 'test_xlsm*.py'
```

Код возврата 0 означает успешное слияние, 1 — конфликт/неподдерживаемый формат.
При ошибке выходная книга не перезаписывается. Перед ручной работой с конфликтом
сохраните все три версии книги; отчёт не заменяет их.

### Выбор ours/theirs локально

После первого запуска сохраните копию `report.json` как `resolutions.json` и
заполните `choice` у каждого элемента массива `conflicts`. Каждый элемент содержит
лист, компонент, колонку и название поля, исходное значение и оба новых значения.
Формулы показываются так, как записаны в исходных ячейках.

```json
{
  "id": "оставьте идентификатор из отчёта",
  "sheet": "Chips",
  "part": "STM32F407VGT6",
  "field": "Description",
  "base": "Микроконтроллер",
  "ours": "Микроконтроллер STM32",
  "theirs": "Микроконтроллер Cortex-M4",
  "choice": "theirs"
}
```

Это пример одного элемента, **не полный файл решений**: сохраняйте `version`,
`inputs`, все идентификаторы и остальные поля полного отчёта.
Затем повторите сборку с теми же исходными книгами:

```sh
python tools/xlsm_merge/merge.py ancestor.xlsm ours.xlsm theirs.xlsm merged.xlsm --resolutions resolutions.json --report resolved-report.json
```

Если разрешаете уже начатый конфликт Git, используйте его три исходных версии
(ancestor/ours/theirs). После успешной сборки замените конфликтующую книгу на
`merged.xlsm`, пересчитайте и сохраните её в Excel, выполните `git add` и
`git commit`, чтобы завершить слияние. Отчёт с решениями сам по себе конфликт Git
не закрывает. Для Git rebase значения ours/theirs могут отличаться от привычных;
проверяйте содержимое обеих исходных книг.

## Правила для команды и границы первой версии

- Добавляйте новые компоненты в конец таблицы. Сортировка/перемещение существующих
  записей блокируется: межстрочные ссылки могут менять смысл.
- `Part Number` должен быть текстовым постоянным уникальным ключом внутри листа.
  Не используйте в нём формулы. Переименование трактуется как удаление/добавление;
  для частых переименований понадобится отдельная колонка постоянного ID и миграция.
- В текущей книге две заполненные строки `Connectors` (70–71) не имеют ключа.
  Они сохраняются на своих местах как непрозрачные записи. Исправьте ключи отдельным
  согласованным изменением до параллельного редактирования этих строк.
- Обычные формулы своей строки переводятся при добавлении второй записи в ту же
  физическую строку. Поддерживаются структурированные ссылки `[@...]`/`[#This Row]`.
  Перенос формул со ссылками на другие строки, абсолютные строки, именованные
  диапазоны или внешние книги требует ручной проверки.
- Изменение колонок, структуры таблиц, стилей, гиперссылок и прочих метаданных
  может потребовать ручного слияния. Массовое оформление делайте отдельным PR.
  Схема не обещает автоматическое объединение любых изменений Excel.
- VBA, XML-карты, связи и прочие части ZIP сохраняются; openpyxl используется
  только для чтения, итоговая книга им не пересохраняется. VBA не запускается.
- Автоматический тест проверяет семантическое совпадение всех ячеек настоящей
  книги и сохранность её пакетных частей. Excel и Altium в CI не установлены:
  открытие без восстановления и работа базы требуют первой ручной проверки.
- `.SchLib` и `.PcbLib` этот инструмент не объединяет.
